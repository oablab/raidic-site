Everything diskutil knows, at a glance

Trouble you can't miss

A degraded set turns its whole card orange. A mirror running on one disk shows No redundancy — even though macOS reports it as "Online". Missing members are called out by name.

Rebuilds, byte-accurate

diskutil shows rebuild progress as a whole percent. Raidic reads the rebuilt bytes directly and shows 0.12% when the rebuild starts and 748 GB / 2 TB as it runs — refreshed automatically every 5 seconds.

Built for real RAID workflows

🖱 Drag a disk in

Drop a physical disk onto a RAID set to add it as a member. Rebuild starts after one confirmation — never silently.

🧱 Degraded RAID1 on purpose

Create a mirror with a single disk, move your data in, then add the second disk later. The classic migration workflow, built in.

🛟 Guardrails everywhere

The boot disk is never offered. Destructive actions require typing the set name. Disks too small for a set are refused before you ever type a password.

🧭 Volumes, mapped

See every mounted volume, its filesystem, mount point and free space — including APFS volumes living inside a container on top of your RAID set.

FAQ

Is Raidic safe to use on disks with data?

Raidic drives the same diskutil engine Apple ships. Listing and monitoring are read-only and need no password. Anything destructive — creating a set, adding a member — shows exactly which disks will be erased and requires typing the set name plus macOS admin authentication.

Can it create a degraded RAID1?

Yes. Pick Mirror and select a single disk — Raidic warns that the set starts with no redundancy, and you complete the mirror later by dragging in a second disk. That triggers a full rebuild with live progress.

Why does my mirror say "No redundancy" when macOS says Online?

macOS reports a single-member mirror as Online because its only member is healthy. But one disk means zero fault tolerance — Raidic flags that state explicitly so you're never surprised.

Does it support APFS on RAID?

Yes. When a RAID set carries an APFS container, Raidic follows the container to the real mounted volume and shows its name, mount point, and free space — the part Disk Utility makes hard to see.

Why isn't my disk offered as a candidate?

Raidic never offers the boot disk or disks that already belong to a RAID set. Disks with stale RAID leftovers from deleted sets are labeled — they're still usable, and creating a new set cleans them up.

Does Raidic send any data anywhere?

No. No network capability, no analytics. It only talks to macOS's own disk management.

Can Apple Silicon Macs boot from AppleRAID?

No — that's a macOS limitation, not Raidic's. AppleRAID is for data and external disks, like a mirrored backup pair.
